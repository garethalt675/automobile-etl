## The open bug — start here

**VAMA June 2026 produced zero member rows while reporting `success`.**

```
2026-04  detail → sales_by_model_region: 82 rows   extracted_tables_long: 3,395
2026-05  detail →                        88 rows                          3,491
2026-06  detail →                         0 rows                          3,240   ← "success"
```

The document downloaded and parsed fine — this is purely `3_Extract_Tables`.
The source is confirmed good: the published PDF at
`http://vama.org.vn/Data/upload/files/2026/BCBH/VAMA%20sales%20report%20June%202026%20-%20Detail.pdf`
is byte-identical to what is already stored (`document_id = a8d5c421a1c7f7b9`).

**Hypothesis, not yet verified:** the year-to-date header failed to resolve. Both
months parse to 3 tables with the same shape, but the column names differ:

```
2026-05 : Maker, Model name, Seat, Sales - May 2026, col_6, col_7, Sales - YTM 2026, Share
2026-06 : Maker, Model name, Seat, Sales - Jun 2026, col_6, col_7, col_8,            Share
                                                                   ^^^^^ no YTM name
```

If the extractor keys on a `YTM`-shaped header, June finds no YTD columns and
emits nothing — while still reporting success.

Testable read-only against stored data, no re-run needed:

```sql
SELECT column_index, column_name, COUNT(*)
FROM market_data.vama.extracted_tables_long
WHERE document_id = 'a8d5c421a1c7f7b9'   -- 2026-06
GROUP BY 1, 2 ORDER BY 1;
-- compare with 886dd181f2848618 (2026-05, good)
```

This costs ~24,000 units of June volume in the gold view, and it is **silent** —
`extraction_status = 'success'`, so the scheduled run on the 15th will not flag it.
Worth fixing before then.

   only then the Databricks secret. The key had been correctly rotated into the
   secret on 2026-07-24 and *nothing read it*, so it presented as an expired key.
   Secret now wins; the file is fallback only. Also moved the key from the URL
   query string into an `x-goog-api-key` header.
2. **`databricks_sync.py push` could never deploy `vama_parser/*.py`** — it guessed

## Rules worth not relearning

- **Never delete a range then conditionally re-insert.** Materialise the
  replacement rows first, then delete only the keys present in them. This shape
  cost two months of Hyundai history on 2026-07-30.
- **Never `MERGE ... WHEN MATCHED THEN UPDATE SET *` from a fallible fetch.** It
  writes NULL over the only stored copy on failure.
- **`max_retries: 0` does not stop a destructive task running twice** — Databricks
  retries `INTERNAL_ERROR` on its own. The task has to be safe to fail.
- **Compare per key, never by table total.** A month lost against a month gained
  nets to zero. `435 → 447` looked fine while hiding a loss.
- **Verify what a URL actually contains before trusting its slug.** Several slugs
  in this project name a different month than the article does, and one host
  returns HTTP 200 with no article at all.
